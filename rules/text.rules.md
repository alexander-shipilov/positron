# Text File Formatting Rules

## 1. Scope and Line Length

- These rules apply to all text-based files in the repository, including
  source code, configuration files, documentation, and Markdown files.

- Every line in a text file MUST NOT exceed **80 characters**.

- **Exceptions:**

  - Breaking the line would violate the syntax of the target language or
    format.

  - The file is automatically generated by a tool.

## 2. Language and Identifiers

- All documentation, comments, commit messages, and rule files MUST be
  written in English.

- String literals in tests MAY include non-English characters when required
  by a specific test scenario.

- All code identifiers, file names, and directory names MUST use ASCII
  letters, digits, and characters permitted by the context (`_`, `$`, `-`,
  `[`, `]`).

## 3. Human-Readable Text Formatting

This section applies to prose blocks in Markdown files, plain text files, and
documentation comments.

- A line MUST NOT begin with a punctuation mark (`.`, `,`, `:`, `;`, `(`,
  `)`, `"`, `'`).

- **Exception:** A line MAY begin with `-` when it introduces a bullet list
  item.

- If an indivisible inline token starts with punctuation and exceeds the
  80-character limit when combined with the preceding word, the preceding word
  or preposition MUST be wrapped to the next line along with the token.

- Paragraphs MUST be separated by a single blank line.

- Consecutive blank lines MUST NOT exceed two lines (two blank lines MAY be
  used to separate major sections).

## 4. Lists

- A list is treated as a separate block and MUST be preceded and followed by a
  blank line.

- In standard Markdown documents, items within the same list do not require
  blank lines between them unless items contain multiple paragraphs.

- In TSDoc comments, every list item MUST be separated by a blank comment
  line (` *`) so that the `@microsoft/tsdoc` parser recognizes the list.

- Continuation lines of a list item MUST align with the first character of the
  item's text.

## 5. Inline Code and Literals

- Programming language literals, identifiers, file paths, and code fragments
  MUST be enclosed in backticks (`` `...` ``).

- If a backtick appears inside an inline code fragment and no context-specific
  escaping rule is defined, it MUST be escaped as `` \` ``.

- Numeric values MUST be enclosed in backticks when used as language literals
  (e.g., `` `value` is equal to `0` ``) and written as plain text when used
  as natural-language quantities (e.g., `repeat 5 times`).

## 6. Typography

- Lines within a prose paragraph SHOULD be wrapped to approximately equal
  visual lengths within the 80-character boundary.
